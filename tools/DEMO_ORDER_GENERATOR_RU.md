# Генератор заказов для демо-магазина

`demo_order_generator.php` создаёт настоящие заказы через классы PrestaShop. Скрипт не зависит от Docker и предназначен для системного cron.

## Установка

1. Скопируйте `demo_order_generator.php` в корень PrestaShop — рядом с папками `config`, `classes`, `modules` и `var`.
2. Убедитесь, что PHP-пользователь cron может записывать в `var/demo-order-generator`.
3. Проверьте план без изменения базы:

```bash
php /path/to/prestashop/demo_order_generator.php --dry-run --count=30
```

4. Проверьте создание одного заказа:

```bash
php /path/to/prestashop/demo_order_generator.php --force=1 --scenario=high_value --outcome=paid
```

## Cron

Запуск каждые пять минут, ровно 30 заказов в день:

```cron
*/5 * * * * /usr/bin/php /path/to/prestashop/demo_order_generator.php --count=30 --max-per-run=3 --coupon-use-rate=35 >> /path/to/prestashop/var/logs/demo-order-generator.log 2>&1
```

Вариант со случайным дневным количеством от 26 до 34:

```cron
*/5 * * * * /usr/bin/php /path/to/prestashop/demo_order_generator.php --min=26 --max=34 --max-per-run=3 --coupon-use-rate=35 >> /path/to/prestashop/var/logs/demo-order-generator.log 2>&1
```

При первом запуске дня скрипт создаёт JSON-план со случайными моментами между 07:00 и 23:00. Последующие запуски создают только наступившие заказы. Если cron временно не работал, за один вызов будет создано не более `--max-per-run` просроченных заказов.

Дата и часы рассчитываются в часовом поясе, настроенном в PrestaShop.

Состояние хранится в `var/demo-order-generator/YYYY-MM-DD.json`. Файловая блокировка защищает от параллельных запусков, а служебный marker заказа — от повторного создания после аварийного завершения.

## Какие ситуации создаются

- первый заказ нового покупателя;
- заказ от 500 для бесплатной доставки;
- заказ от 100 до 500 для повышенной процентной скидки;
- заказ от 50 до 100 с минимальной суммой следующей корзины;
- товары категории Clothes;
- товары Studio Design вне Clothes;
- покупатели из Франции и США;
- заказ в USD из другой страны;
- покупка без категории Accessories;
- fallback-заказ с Accessories;
- разные финальные статусы: ожидание оплаты, оплачен, в обработке, отправлен, доставлен, отменён и возвращён.

Для повторных заказов используется пул из 40 постоянных демо-покупателей с разными email. Каждый из них сохраняет собственную историю заказов и собственные купоны. Внутри одного созданного плана адреса распределяются по кругу без повторов, пока пул не закончится. Покупатель заранее фиксируется в JSON-плане конкретного заказа, поэтому повторный запуск cron не поменяет email. Для сценария первого заказа каждый раз создаётся отдельный адрес вида `new.<идентификатор-заказа>@example.test`.

Если у выбранного постоянного покупателя ещё нет успешных заказов, скрипт автоматически создаёт ему один исторический заказ в статусе Delivered. Такой bootstrap-заказ не входит в дневной лимит и позволяет затем показать получение и использование персонального купона.

Язык каждого покупателя и заказа выбирается из активных языков текущего магазина. Для постоянных покупателей язык стабилен: один и тот же email продолжает заказывать на одной локали. Новые покупатели также распределяются между доступными языками. ISO-код сохраняется в поле `language` JSON-плана, а заказ получает соответствующий `id_lang`; этот же язык используется модулем при подготовке письма с купоном. Если в магазине активен только один язык, все заказы останутся на нём.

У повторного покупателя часть успешных заказов применяет персональный код, который ранее был отправлен модулем `set_next_order_discount`. Вероятность задаёт `--coupon-use-rate` от 0 до 100; по умолчанию это 35%. Генератор выбирает только купоны модуля со статусом `emailed` или `reminded` и перед добавлением вызывает штатную проверку PrestaShop. Поэтому просроченный, уже использованный, чужой или неподходящий по минимальной сумме код не применяется.

После оформления заказа обычный hook модуля переводит применённый купон в `used`, записывает дату использования и номер заказа. Сам генератор напрямую статус купона не меняет. Для первого заказа, ожидания оплаты, отмены и возврата купоны автоматически не используются. Значения `--coupon-use-rate=0` и `--coupon-use-rate=100` удобны для проверки веток без использования и с обязательной попыткой применения соответственно.

После оформления остаток выбранного товара восстанавливается до исходного значения, поэтому ежедневная демонстрация не опустошает каталог.

Для полного набора сценариев в магазине должны быть активны страны US, France и Denmark, валюты USD и EUR, а также доступные физические товары в категориях Clothes, Accessories и Art. Генератор выводит понятную ошибку, если обязательная страна или валюта отсутствует; для отсутствующего типа товара он использует любой доступный физический товар и пишет предупреждение.

## Управление

Показать состояние плана:

```bash
php demo_order_generator.php --status
```

Создать три заказа сразу:

```bash
php demo_order_generator.php --force=3
```

Для воспроизводимого теста можно зафиксировать и сценарий, и финальный статус:

```bash
php demo_order_generator.php --force=1 --scenario=clothing --outcome=processing
```

Гарантированно попытаться применить ранее отправленный купон в тестовом заказе:

```bash
php demo_order_generator.php --force=1 --scenario=high_value --outcome=paid --coupon-use-rate=100
```

Доступные сценарии и параметры:

```bash
php demo_order_generator.php --help
```

Скрипт работает только через PHP CLI. При открытии его URL в браузере он возвращает 404, поэтому публичный корень сайта не создаёт дополнительную HTTP-точку запуска.
